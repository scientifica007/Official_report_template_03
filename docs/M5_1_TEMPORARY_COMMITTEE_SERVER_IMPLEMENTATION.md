# M5.1 — الحسابات المؤقتة لأعضاء لجنة الترسيم

**02/11/2026 — الحالة: التنفيذ البرمجي موجود؛ غير مفعل في الإنتاج.**

## ما نُفذ
- ترحيل Supabase رقم 007: جداول مهام الترسيم، ثلاثة مقاعد، مساهمات لا تُعدّل بعد الإرسال، سجل أحداث، RLS وصلاحيات منفصلة عن حسابات المفتشين.
- RPC لإنشاء المهمة، حفظ وإرسال مساهمة العضو، وإغلاق المهمة؛ يتحقق الخادم من صحة العلامات وحدودها ومن مضاعفات نصف نقطة.
- وظيفة Edge بعنوان titularisation-access: إنشاء حساب Auth مؤقت لكل مقعد، وتسجيل الدخول باسم مستخدم وكلمة مرور، وإعادة إصدار الكلمة، وسحب الصلاحية وحذف حساب Auth بعد انتهاء المهمة.
- لوحة رئيس اللجنة في المنصة؛ موقع دخول خاص بالعضو على الهاتف والحاسوب، مع الإملاء الصوتي.
- جسر اختياري لنقل مساهمات الأعضاء المرسلة إلى مسودة تقرير المفتش دون تغيير علاماته أو تقديراته النهائية. تظل مولدات PDF وDOCX وJSON المقبولة دون تعديل.
- العلم temporaryCommitteeEnabled في cloud-config.js يساوي false افتراضيًا، حتى لا تُعرض وظائف غير جاهزة على المستخدمين.

## متطلبات التفعيل بعد الاختبارات
1. إنشاء مشروع Supabase تجريبي منفصل وتطبيق الترحيلات 001–007 عليه، دون بيانات حقيقية.
2. تشغيل الاختبارات السلبية على RLS: عضو يحاول الوصول إلى بيانات عضو آخر؛ عضو انتهت صلاحيته أو أُلغي وصوله؛ مفتش غير مالك؛ زائر غير مصرح؛ محاولة تعديل مساهمة مرسلة؛ ومحاولة تجاوز سقف العلامات.
3. نشر وظيفة Edge في المشروع التجريبي. أسرار SUPABASE_URL وSUPABASE_ANON_KEY وSUPABASE_SERVICE_ROLE_KEY لا توضع في GitHub Pages.
4. ضبط COMMITTEE_LOGIN_DOMAIN على نطاق بريد تتحكم فيه وليس نطاق شخص آخر أو example.com، وضبط COMMITTEE_ALLOWED_ORIGIN على https://scientifica007.github.io. الحسابات مؤقتة ولا تستخدم بريد الأعضاء الحقيقي.
5. اختبار إنشاء ثلاثة حسابات وإصدار بيانات دخول كل عضو مرة واحدة، وتغيير كلمة مروره ثم إلغاء وصوله في أثناء جلسة مفتوحة.
6. بعد إغلاق المهمة، إلغاء الحسابات وحذفها مع التأكد من بقاء المساهمات المرسلة. إغلاق المهمة وإلغاء الوصول مختلفان عن محو السجلات المهنية.
7. اختبار جلب المساهمات المرسلة إلى مختبر الترسيم، ومطابقة التقارير PDF/DOCX وملف JSON والرقم المرجعي للشبكة.
8. بعد النجاح والموافقة الصريحة على التفعيل الإنتاجي، تطبيق الترحيل على مشروع الإنتاج ثم ضبط temporaryCommitteeEnabled على true.

## حدود وأمان
- شبكة الخمسة والعشرة فقط في هذه الشريحة؛ الشبكة التحليلية ذات 14 مؤشرًا تتطلب تجميد الأوزان والتحقق منها في الخادم أولًا.
- لا ترسل كلمة المرور في الرابط ولا في JSON أو سجل GitHub. تُعرض مرة واحدة للمفتش، ثم يُخفيها.
- تغيير كلمة المرور لا يبطل بالضرورة رموز JWT القائمة؛ زر الإلغاء يسحب صلاحيات قاعدة البيانات فورًا حتى إذا بقي الرمز صالحًا تشفيريًا.
- لا يجوز فتح وظيفة إنشاء الحسابات بلا تحقق من JWT المفتش المعتمد وملكيته للمهمة.
- عند حذف حساب Auth، يبقى سجل المساهمة مرتبطًا بمقعد اللجنة؛ لا تُحذف المساهمة ضمنيًا.
- الاختبارات الآلية الثابتة لا تثبت سلامة RLS الإنتاجية. يلزم التحقق الفعلي على خادم Supabase تجريبي قبل إعلان ميزة الحسابات PASS.
