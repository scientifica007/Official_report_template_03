# ARCH-01C / DR-003 — تحرير أوزان المؤشرات داخل سقف كل معيار

> **قرار المستخدم — 18/10/2026:** يجوز اعتماد **أوزان متفاوتة** لمؤشرات الشبكة التحليلية المشتقة من شبكة الخمسة، مع إتاحة **تعديل الأوزان عند إعداد مهمة الترسيم** ما دام مجموعها يساوي سقف المعيار الأم (مثلًا /8 للقدرات المهنية).
>
> **حالة القرار:** **اعتماد المبدأ الوظيفي ودقة الأوزان بمقدار نصف نقطة (0.5)، والسماح بالوزن صفر (0)** بقرار المستخدم اللاحق. ليست هذه أوزانًا مقررة رسميًا ولا موافقة على تغيير قاعدة البيانات أو إطلاق محرر في الإنتاج. مرجع العدد [DR-002 — المؤشرات الـ14](ARCH01C_THREE_RUBRIC_SELECTION.md)، ومرجع الرتب وبقية الاختلافات [DR-001](ARCH01C_ALL_RANKS_RUBRIC_DECISIONS.md).

## 1. الثوابت التي لا يجوز تغييرها من محرر الأوزان

| المعيار | عدد المؤشرات الثابت | سقف المعيار الثابت | مثال توزيع أولي **غير ملزم ولا رسمي** |
|---|---:|---:|---|
| التنشيط | 3 | 12 | 4 + 4 + 4 |
| القدرات المهنية | 3 | 8 | 3 + 3 + 2 |
| السيرورة | 4 | 8 | 2 + 2 + 2 + 2 |
| التلخيص والتحكم | 2 | 6 | 3 + 3 |
| التحضير لحصص التدريس | 2 | 6 | 3 + 3 |
| **المجموع** | **14** | **40** | **40** |

الأمثلة أعلاه تصلح **قيمًا إرشادية في محرر تجريبي** فقط؛ ولم يصرح المستخدم باعتماد توزيع بعينه بوصفه افتراضيًا نهائيًا أو وزاريًا. لا يسمح تعديل الأوزان بتغيير نص المؤشر أو نقله إلى مجموعة أخرى أو تغيير سقف المجموعة.

**مثال واحد لمسار تعديل داخل المعيار نفسه (/8):** إذا كانت القدرات المهنية تحتوي ثلاثة مؤشرات، يستطيع المفتش التعديل من `3+3+2` إلى `4+2+2` أو `2+4+2`، وتقبل النسخة فقط عندما يساوي المجموع **8 بالضبط**. تصبح درجة كل مؤشر ضمن مجاله الفردي `0..max_points`، ولا ينبغي مساواة الخانة الفارغة بالصفر.

## 2. واجهة الإعداد المقترحة

1. يختار المفتش **الشبكة الثالثة التحليلية، 14 مؤشرًا** من شبكات الترسيم الثلاث عند إعداد المهمة.
2. يظهر جدول المجموعات الخمس والمؤشرات المنسوبة إليها من مصدر PDF، وبجانب كل مؤشر خانة **«الوزن الأقصى لهذا المؤشر»** وحقل منفصل لاحقًا لعلامة الأداء المحصلة.
3. يظهر شريط حساب لحظي **«المجموع: 7 من 8 — الباقي: 1»** أو **«المجموع: 9 من 8 — زائد: 1»**. يسمح بتعديل المسودة، لكن يمنع **تثبيت الملف** أو بدء التنقيط حتى يصبح المجموع مطابقًا لسقف كل معيار بلا زيادة أو نقص.
4. زر **«توزيع إرشادي»** يعرض الأوزان الأولية أعلاه **مع تنبيه بأنها اقتراح قابل للتعديل وليست قواعد رسمية**. لا تُفرض القيم على المفتش عند اختيار الشبكة دون اطلاعه.
5. زر **«تثبيت توزيع الأوزان لهذه المهمة»** يحتاج خطوة مراجعة صريحة؛ يُعرض جدول الخمسة والمجموع /40، ويحفظ مصدر الملف ونسخته وتاريخ تثبيته.
6. في شاشات أعضاء اللجنة لا تظهر حقول تعديل الوزن أثناء وضع العلامة؛ تظهر **الحدود المجمدة المشتركة** للمهمة. وقد يُسمح بواجهة مقارنة أو طباعة الإعداد، لا بتغييره خفية.

## 3. عقد صحة البيانات

لأي مجموعة `g` ذات حد أقصى `group_cap[g]` ومجموعة مؤشرات `I(g)`:

```text
sum(weight[g,i] for i in I(g)) == group_cap[g]   # equality, not <=
group_cap = [12, 8, 8, 6, 6]
sum(group_cap) == 40
score[g,i] is empty OR (0 <= score[g,i] <= weight[g,i])
# weight=0 is valid and retains indicator identity; score=0 differs from empty.
group_score = sum(score[g,i])   # after applying documented completeness rule
lesson_score = sum(group_score)  # only if all five groups complete
```

- **قرار معتمد لدقة الأوزان:** أصغر وحدة لتعديل وزن المؤشر هي **0.5 نقطة**؛ يُقبل الوزن إذا كان مضاعفًا صحيحًا لنصف نقطة وكان ضمن حدود معياره، ويُرفض وزن مثل 1.25 أو 2.75. **تحديث بعد التجربة الميدانية (18/10/2026):** طالب المستخدم بأن تكون **العلامة المحصلة أيضًا بخطوة 0.5 نقطة** في جميع شبكات الحصة والمناقشة؛ لا يقتصر القرار على أوزان المؤشرات.
- **مقترح تنفيذ حسابي:** التخزين والتحقق عبر عدد صحيح من **أنصاف النقاط** (`half_units = weight × 2`) بحيث تصبح حدود المجموعات 24،16،16،12،12 نصفَ نقطة (ومجموع الحصة 80)، ثم يُعرض الوزن الفعلي بقسمة الوحدات على 2. بهذه الطريقة نتجنب اختلافات الفاصلة العائمة عند اختبار المساواة الدقيقة.
- **قرار معتمد (18/10/2026): الوزن صفر مسموح صراحةً**؛ القيمة الدنيا للوزن **0** وليست 0.5، بينما أصغر خطوة *غير صفرية* هي 0.5. أي وزن مسموح ينتمي إلى المجموعة `0, 0.5, 1.0, 1.5, ...` حتى سقف المعيار. يظل المؤشر ذو الوزن صفر ضمن المؤشرات الـ14 مع حقول الوصف/الملاحظة؛ لا تُحذف هويته ولا يُعد ذلك إلغاءً للمعيار الأم. **منع التباس البيانات:** وزن 0 قيمة ضبط صريحة، وعلامة الأداء 0 قيمة تقييم صريحة، والحقل غير المعبأ (`null`) عدم إدخال. قواعد إلزام إدخال العلامة عند وزن 0 تُحسم في مواصفة محرر الدرجات؛ لا نضع علامة تقييم صادرة عن المفتش تلقائيًا نيابة عنه.
- كل مجموعة يُقفل ملف وزنها فقط إذا أكملت مجموعها الثابت؛ جمع حد أقصى 8 بمعيار آخر 8 لا يسمح بإزاحة نقطة بين المجموعتين.
- **التقييم غير المكتمل:** إذا غاب تقييم مؤشر **ذي وزن أكبر من صفر** فلا تُكتمل علامة الحصة. أما المؤشر ذو الوزن صفر فيظل ظاهرًا؛ تُحدد مواصفة محرر التقييم لاحقًا هل يسجل «غير منقّط» صراحةً أم تظهر خانته للقراءة فقط، **دون إنشاء درجة تقييم أو حكم نيابة عن المفتش**. درجة صفر مدخلة صراحةً لا تساوي غياب إدخال.

## 4. «الشبكة» و«ملف الأوزان» كيانان مختلفان

**تعريف الشبكة** يثبت منشأها وبنيتها: `lesson_derived_indicators_v1`، المعايير الخمسة، المؤشرات الأربعة عشر، الحدود `[12,8,8,6,6]`، الحالة `derived_inspector_unapproved`.

**ملف توزيع الأوزان للمهمة** يُنشئه المستخدم لتلك المهمة: `weights_profile_id`, `weights_profile_revision`, `mission_id`, `rubric_id`, `rubric_version`, خريطة `indicator_id → weight`, `status`, `created_by`, `confirmed_by`, `confirmed_at`. يتم تثبيت الملف أو معرف نسخة ثابتة منه في كل `evaluation_session` لضمان عدم إعادة تفسير الدرجات المحفوظة بعد سنوات.

*مثال بيانات اصطناعية للاسترشاد، وليس عقد SQL نهائيًا:*

```json
{
  "rubric_id": "lesson_derived_indicators_v1",
  "rubric_version": 1,
  "weights_profile_id": "mission-specific-profile",
  "weights_profile_revision": 1,
  "status": "FROZEN_FOR_SCORING",
  "group_caps": [12, 8, 8, 6, 6],
  "indicator_weights": {
    "LESSON_1_A": 4, "LESSON_1_B": 4, "LESSON_1_C": 4,
    "LESSON_2_A": 3, "LESSON_2_B": 3, "LESSON_2_C": 2,
    "LESSON_3_A": 2, "LESSON_3_B": 2, "LESSON_3_C": 2, "LESSON_3_D": 2,
    "LESSON_4_A": 3, "LESSON_4_B": 3,
    "LESSON_5_A": 3, "LESSON_5_B": 3
  }
}
```

**هذه رموز تحليلية أولية** وليست معرّفات نهائية مقررة من المصدر؛ يجب تثبيت جدول المؤشرات ومعرّفاتها قبل إنتاج JSON الرسمي أو إنشاء قاعدة جديدة.

## 5. متى يجوز تعديل الوزن؟

| وضع المهمة | تعديل الأوزان | أثره |
|---|---|---|
| مهمة جديدة؛ لم تُسجّل درجات ولا تبدأ جلسة تقييم | **مسموح في الإعداد** للمخوّل مهنيًا، حتى تصبح المجاميع صحيحة ويؤكد التثبيت | اعتماد ملف توزيع محدد وإصداره |
| مهمة مشتركة بدأ فيها التقييم لدى عضو أو أكثر | **ممنوع كتعديل صامت للنسخة المجمدة** | جميع التقييمات تشير إلى النسخة التي بدأت بها |
| ضرورة مهنية لتغيير الوزن بعد تسجيل درجات | يُدرس **إصدار توزيع جديد** بعملية صريحة موثقة ومراجعة صلاحيات اللجنة؛ لا نقل أو تعديل الدرجات آليًا | الحفاظ على التوزيع والعلامات القديمة للمراجعة، وإنشاء جلسة تقييم جديدة أو إعادة تنقيط مبررة |
| تقرير أو محضر مغلق/معتمد | **لا تغيير رجعي** | نسخة تاريخية ثابتة المصدر والحساب |

**في المهمة الجماعية:** حتى لو أعد المفتش المسؤول ملف الأوزان، فلا يعني إنشاء المهمة امتلاك سلطة عامة على بقية المفتشين في نموذج 03. قواعد لجنة الترسيم اختصاص مستقل يتطلب تحديد من يختار ويثبت، وكيف تُخطر اللجنة عند أي إعادة ضبط؛ ليس مجرد إتاحة تعديل لكل حساب.

## 6. متطلبات المخرجات والتدقيق

- تحفظ الوثيقتان **التقرير والمحضر** النتائج المحسوبة من **نفس جلسة التقييم وملف الأوزان المجمد**؛ لا يمكن توليد محضر بدرجات وفق توزيع آخر.
- تقرير الشبكة التحليلية ينبغي أن يوضح لكل مؤشر **وزنه الأقصى ودرجته المحصلة** مع مجموع مجموعته، لا أن يتظاهر بتطابق جدول الخمسة التاريخي.
- ملف JSON يحفظ البنية ومصدر الشبكة وحالة الاعتماد غير الرسمي وملف الأوزان ونسخته ومصدر كل علامة ومؤلفها؛ لا يحرر أسماء المؤشرات بناءً على الاجتهاد دون تغيير إصدار.
- تنبيهات الطباعة/التصدير تحظر إخراج نسخة **جاهزة للاعتماد** إذا كانت الأوزان أو العلامات ناقصة؛ سياسة تصدير المسودات للمراجعة تُحسم لاحقًا.
- لا يتم تعديل بيانات قوالب التفتيش المعمق 03 أو RLS/SQL الحالي في هذه الخطوة.

## 7. اختبارات القبول المنتظرة لمحرك تجريبي معزول

- قبول `3+3+2=8` و`3+2.5+2.5=8` و`3.5+2.5+2=8` و**`5+3+0=8`** في القدرات المهنية؛ رفض `4+3+2=9` و`3+2+2=7` وأي وزن لا يقع على مضاعفات 0.5 مثل `2.25` أو `2.75` عند التثبيت.
- قبول وزن المؤشر = **0** دون حذفه من التعريف أو خلطه مع قيمة وزن غير مدخلة؛ رفض الأوزان السالبة وغير الصالحة والكسور التي لا توافق 0.5 والوزن الذي يتجاوز سقف مجموعته.
- الاحتفاظ بكل مؤشرات المجموعات **3+3+4+2+2** ومجاميع الحدود **12+8+8+6+6=40**.
- عدم تحويل العلامات أو التقييمات من ملف وزن إلى آخر تلقائيًا.
- منع تغيير الأوزان أثناء تقييم مشترك قائم أو عند صدور تقرير معتمد، مع اختبار إصدار نسخة جديدة بطريقة موثقة.
- اختبار حالة علامة **صفر مدخلة** مقابل **خانة فارغة** لا تسمح بإكمال المجموع.
- حساب نهائي متطابق عند الاستيراد وإصدار تقرير ومحضر وJSON.
- مرور جميع اختبارات نموذج 03 دون تغيير، واستخدام أسماء مترشحين وأعضاء اصطناعية في الاختبارات.

## 8. القرارات التي بقيت مفتوحة بعد اعتماد نصف النقطة

1. **حُسمت دقة الأوزان والعلامات المحصلة:** أصغر خطوة هي **0.5 نقطة** مع جواز الصفر في جميع شبكات الحصة والمناقشة، وترفض أرباع النقطة مثل 1.25. **تبقى طريقة تقريب /20 بعد القسمة على 3** مسألة منفصلة لم تُحسم.
2. **حُسم جواز الوزن صفر:** لا يحظره المحرر. المتبقي تحديد تمثيل خانة *العلامة المحصلة* عندما يكون وزن المؤشر صفرًا (غير منقّط/للقراءة فقط) دون تغيير معنى العلامة الفعلية صفر أو الملاحظة المهنية.
3. كيف يُعتمد تغيير التوزيع المهني بعد بداية التنقيط وفق صلاحيات أعضاء اللجنة؟
4. شكل القالب الطباعي التحليلي وموافقته المهنية؛ شبكة المؤشرات الجديدة **غير معتمدة رسميًا**.

**المحصلة:** **اعتمد المستخدم اختلاف الأوزان وتعديلها داخل سقف كل معيار، وخطوة وزن 0.5، والسماح الصريح بوزن صفر.** لا يظل توزيع الأوزان ثابتًا على جميع المهمات. حُسمت **خطوة العلامة المحصلة = 0.5** في جميع الشبكات والمناقشة؛ بقي حسم سياسة **تقريب /20** وسلوك خانة الدرجة عند وزن صفر؛ التطوير التالي نموذج إدخال أوزان آمن وقابل للاختبار قبل أي تعديل سحابي.
