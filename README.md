# Official Report Template 03 — النسخة التنفيذية الأولى

محرّر عربي (RTL) لتقرير **التفتيش المعمق / النموذج 03** بمرجع بصري `Official_report_template_03.pdf`.

## النطاق المنفذ
- إدخال بيانات المهمة والمؤسسة ورئيسها والمفتشين المشاركين في الغلاف.
- فهرس 11 باباً و39 مجالاً (38 مجالاً من الأبواب II–VIII، ومجالًا عاماً إضافياً للباب IX)، مع 176 عنصرًا تفصيليًا (إعادة تفصيل خمسة مؤشرات مركبة دون إنشاء معايير تنظيمية جديدة).
- معاينات وتوصيات متعددة لكل مجال/عنصر، مع تصنيف اختياري مستقل: مطابق / غير مطابق / غير معني / لم يُقيّم بعد. تحفظ الحالات في JSON وتظهر في DOCX وPDF عند تحديدها، دون إضافة أعمدة جديدة للنموذج الرسمي أو توليد أحكام تلقائية.
- استخراج **JSON حقيقي** وإعادة استيراده، و**DOCX قابل للتحرير** يُولد في المتصفح دون مكتبات خارجية، و**PDF من نافذة طباعة المتصفح** (اختر: حفظ بتنسيق PDF).
- لا قاعدة بيانات ولا تسجيل دخول ولا تسجيلات تحليلية ولا تخزين محلي تلقائي: الحالة داخل ذاكرة التبويب فقط؛ ويمكن مسحها فورًا. أغلق التبويب فتنتهي الحالة. ينبغي تصدير JSON قبل الإغلاق لاستئناف العمل.

## قيود يجب عدم إخفائها
- **هذا الإصدار تجريبي وغير معتمد لإصدار وثائق نهائية.** الفهرس مستخرج بصورة أولية من DOCX ولم يُدقق عنصرًا عنصرًا أمام PDF. عدد المؤشرات ليس حصرًا نهائيًا. يمنع وصف المطابقة البصرية بأنها 100% قبل اجتياز اختبارات المقارنة.
- تصدير PDF يتم عبر `window.print()` وحوار الطباعة، لا بتنزيل ملف PDF مباشر. يتأثر توزيع الصفحات والخطوط بمحرك الطباعة لدى المستخدم.
- DOCX مُنتج من الصفر بتقريب رسمي قابل للتحرير، ولم يُتحقق بعد من التطابق البصري الكامل مع PDF.
- ورود أسماء عدة مفتشين في الغلاف **لا يعني تفعيل حساباتهم أو تعاونهم الفعلي**. ميزة الفريق المتساوي واقتراحات أحد المفتشين في مجال الآخر تستلزم Backend آمنًا، وستضاف في مرحلة مستقلة؛ لا نحتفظ بالتقارير المنجزة طويلًا، ويمكن بناء جلسات مؤقتة تحذف عند الانتهاء.
- «اعتماد» التقرير وتوقيعات المفتشين غير مطبقين. المخرجات معلّمة كمسودات.

## التشغيل

```
python3 -m http.server 8000
```

افتح `http://localhost:8000`. لا حاجة إلى أي مفاتيح أو حسابات لتجربة المحرر.

## الاختبار والنشر

تحقق سريع: `node --check app.js` و`python3 -m json.tool catalog.json >/dev/null`. للنشر العام افتح Settings → Pages → Build and deployment → Source واختر `GitHub Actions`. بعد التفعيل شغّل مسار `Deploy Official Report 03 (static)` من Actions، أو ادفع تغييرًا إلى الفرع `main`. سيتم نشر موقع ثابت بلا خادم خلفي.

## سياسة الاحتفاظ بالبيانات

الافتراضي **عدم حفظ أي تقرير منجز في خادم**، وعدم استعمال `localStorage` أو IndexedDB. يجب تنبيه المستخدم عند مسح البيانات وتوفير التصدير بصيغ JSON وDOCX وPDF. عند تطوير العمل المشترك مستقبلًا يجب تخزين المسودات النشطة تخزينًا مؤقتًا مشفرًا بضوابط وصول، ثم حذفها وفق سياسة معلنة دون ادعاء ضمان محو النسخ الاحتياطية فورًا.

## تحسينات تجربة المستخدم M1.4
- بقي الباب I «التعريف بالمؤسسة» في النسخة المطبوعة، لكن حقوله تُحرر مرة واحدة فقط بصفحة بيانات المؤسسة، دون تقييم أو معاينة وتوصية إضافية مستقلة.
- حقل اختياري لرابط Google Maps للمؤسسة، لا يفتح جهة خارجية حتى يضغط المستخدم على الزر. يُصدَّر الرابط ضمن البيانات والمستندات عند إدخاله.
- تقسيم 5 مؤشرات مركبة إلى 26 بند فحص مستقل (15 بندًا في المظهر العام)، مع الاحتفاظ بنص المصدر ومعرّفه لكل بند.
- لا ينتقل التقييم القديم لمؤشر مركب إلى أي بند فرعي. تُنقل معايناته وتوصياته إلى المجال الأب وتُحفظ حالته القديمة في `legacyAssessments` بملف JSON للمراجعة دون اختلاق حكم على بند جديد.
- إضافة الترجمة العربية: «الانغماس المهني للمكوّنين (Immersion professionnelle des formateurs)».
- تظل خانة «لم يُقيّم بعد» غير مُصدّرة في النسخة الرسمية، ولا تُحوَّل إلى معاينة.

## إصلاح التصدير M1.5 — المعاينات والتوصيات
- تبقى المسودات المكتوبة في حقول الإدخال داخل ذاكرة التبويب عند تغيير الباب أو المجال، وتُضم تلقائيًا إلى التقرير عند اختيار «الإصدار والتصدير»، حتى دون الضغط على «إضافة المعاينة» أو «إضافة التوصية». ويظل زر الإضافة متاحًا لتسجيل فقرات إضافية.
- الجداول الصادرة (PDF وDOCX) تتألف من أربعة أعمدة: **تعيين المجال | عناصر الفحص والرقابة | المعاينات | التوصيات**. يقابل كل عنصر سطر مستقل وتظهر معايناته وتوصياته في العمودين الموازيين له. معاينات المجال العامة تظهر في سطر مستقل عند وجودها.
- PDF: صفحات الغلاف والمقدمة والختام عمودية، بينما تستخدم صفحات جداول الفحص مقاس **A4 أفقيًا** بواسطة CSS named pages. قد يختلف الدعم حسب محرك طباعة المتصفح؛ يُنصح باستخدام Chromium/Chrome بإلغاء رؤوس الصفحات وتذييلاتها عند الحفظ.
- DOCX: جدول Word قابل للتحرير بأربعة أعمدة، وتبديل قسم الصفحات إلى **A4 أفقيًا** أثناء الجداول، ثم الرجوع إلى الاتجاه العمودي عند الخاتمة.
- لا يظهر النص «لم يُقيّم بعد» في التقرير؛ الحالات الإيجابية المختارة فقط تظهر بجانب المؤشر. لا يتم اختلاق معاينات أو توصيات تلقائية.
- ملفات JSON القديمة التي لا تتضمن معاينات فعلية لا يمكن استعادة نصوصها المفقودة؛ يرجى إعادة إدخالها بعد تحديث الموقع.
- **حالة المطابقة:** لا تزال البنية قيد المراجعة الطباعية البصرية مقارنة بنموذج PDF الرسمي. التصدير ما زال تجريبيًا.

## تصحيح مخرجات PDF M1.6
- ثُبتت حالة التقييم المختارة («مطابق»، «غير مطابق»، «غير معني») بشكل بارز داخل خلية «عناصر الفحص والرقابة» لكل مجال/مؤشر. لا تُعرض حالة «لم يُقيّم بعد». تظهر الحالة أيضًا بنص عريض في ملف Word.
- عُطّلت خانات هوامش الطباعة الست (أعلى/أسفل، يمين/وسط/يسار) باستخدام CSS `@page` وتحديد `content:""` على صفحات الغلاف A4 العمودية وجداول الفحص A4 الأفقية؛ هذا يمنع Chrome/Chromium الحديث من إدراج التاريخ والوقت وعنوان الصفحة ورابط الموقع الآلي، مع المحافظة على الهوامش.
- خُصص تنبيه احتياطي لمتصفحات قد تتجاهل CSS الخاص بهوامش الطباعة: ألغِ خيار «الرؤوس والتذييلات» (Headers and footers) داخل نافذة الطباعة إذا ظهر.
- نُقل التنبيه الداخلي للنسخة التجريبية إلى متن المقدمة لمنع توليد صفحة شبه فارغة تحتوي التنبيه وحده.
- لا تُحذف عناوين المواقع التي يكتبها المفتش عمدًا داخل بيانات المؤسسة أو غرض مهمة التفتيش؛ المطلوب حذف إضافات المتصفح غير الرسمية فقط.
